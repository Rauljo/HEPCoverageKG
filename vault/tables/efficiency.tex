\caption[What each configuration costs]{The cost of each configuration on the
supervisor's nine questions, clean records only. \emph{Calls} is every LLM call
the answer required, the planner's own plus the search critic's, the answer
critic's and the plan reviewer's, recovered per record rather than estimated.
Tokens are the planner's and the plan reviewer's; the critics compute their token
usage and never store it, so token counts are a \emph{lower bound} wherever a
critic is present, while call counts are complete. Three readings stand out.
Qwen3.8-flash consumes roughly ten times the input tokens of either 32B planner
for comparable quality --- 191{,}535 against 20{,}578 on the typed agent at the
same F$_1$ --- so its retrieval breadth is bought with reading, not converted
from it. The free-SQL agent is the cheap interface at 2.8--3.8 calls against the
typed agent's 7.0--7.3, and on Qwen3-32B costs \$0.0031 per answer against
\$0.0052, so the typed agent's $+0.147$ F$_1$ and its mechanical provenance cost
about $1.7\times$. Chaining is the most expensive mechanism measured, roughly
doubling calls, rounds and wall time for the largest single F$_1$ gain, while
anchoring moves in the opposite direction on every axis. Dollar figures are
derived from measured spend rather than a price list: one 27-record Qwen3-32B run
billed \$0.25 against 1{,}081{,}881 recorded tokens, giving \$0.231 per million,
which is an upper bound on the price of a recorded token because the critics'
tokens are missing from the denominator. QwQ was self-hosted and has no marginal
cost; no billing anchor exists for Qwen3.8-flash, so no figure is quoted for it.
Wall time is reported last and should be read only within a lane: cluster runs
shared one vLLM server with up to four concurrent evaluation jobs and the hosted
runs contend with other tenants, which is why calls and tokens are the primary
currency throughout this work.}
