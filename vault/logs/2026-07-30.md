## Happened

- **Query layer begun** — `query/schema_card.py`, `query/templates.py`, `query/prompts.py`.
  **215 tests green.**
- **Two silent traps found by measuring the pilot data**, both now encoded in tested SQL:
  - **60 of 272.** `paper_reports_result` links only the *headline* result of each paper. The join
    that works is `entity_occurrence.paper_id`, filled by the importer for all 272. The predicate is
    the semantically obvious choice — and it is exactly what a model writing free SQL would pick.
  - **Rows are not facts.** One fact can be several assertions when a paper states it twice, each
    with its own quote (219 of 251 duplicate triples cite *different* evidence — the graph working,
    not a defect). `paper_reports_result` doubles every one of its 60 facts.
  Both fail with no error and no empty result. Together they are a **self-discovered argument for
  S-04** that is stronger than the Spider 2.0 numbers, because it comes from this data.
- **56 distinct Pythia entities.** Asking about one returns 1 paper; the true answer is **58**.
  Merging them would be *wrong* (PYTHIA 6 ≠ PYTHIA 8) — they want **grouping**, not deduplication.
  Concrete evidence for a layer that had been parked as uncertain.
- **Benchmarked SQLite**: 0.29 ms per template query, 16 ms for the heaviest crosstab, and threads
  make it *slower*. One LLM call ≈ 3,000–17,000 queries.
- Also measured: `result` = one finding, papers hold **1 to 44**; systematics extraction is **good**
  (sampled 20, all genuine named physics systematics); full predicate kind-distributions cost only
  ~300 tokens, so the "mixed" threshold was removed.

## Decided

- **S-23** accepted-view parked · **S-24** free-form escape hatch, flagged, and its log is the spec
  for the next templates · **S-25** dual-path template-vs-free comparison, with two safeguards
  (the free answer must have *executed*; compare structurally before asking a model) ·
  **S-26** learned lessons go into code > schema card > guards > prompt, in that order, and the
  prompt is amended by proposal only · **S-27** one planner, batched operations, hierarchy only
  under context pressure, with a max-concurrent-places dial so 1-vs-many is a parameter sweep ·
  **S-28** clusters collapse, groups expand, merges shown beside the numbers they change.
- The **primitive set changed** for a chaining agent: `describe` / `subjects_of` / `papers_of` /
  `count` / `quotes` as primitives, `list` / `compare` / `crosstab` as conveniences. `subjects_of`
  (the backward hop) did not exist and without it an agent can only walk one direction.
- Fact keys now resolve through `entity_canonical`, so **counting is dedup-sensitive** — which is
  what S-11's dedup-sensitive questions need in order to discriminate at all.
