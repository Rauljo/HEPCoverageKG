# 2026-07-29 — the system around the KG: designed and written down

## Happened

- **The whole system was designed.** Written up as [`../system.md`](../system.md) **v1** — the
  reference document from here on. S-01 … S-22. `overview.md` now points at it.
- **Project framing changed** (after a supervisor conversation): from *gap finding* to **coverage
  review** — helping a physicist see what has been covered while reviewing or planning. Gap finding
  is one use of the map, not the point, and is now future work.
- **The final-state plan was found to be built on a wrong reading of the data.** Measured
  `hepkg.db` directly: 161 `result_has_final_state` assertions across all 60 papers, **zero** with a
  `count` qualifier, 34% with no qualifier at all, and **no fan-out** into object edges — the whole
  signature sits on one node as English prose ("Exactly one lepton plus ≥4 b-tagged jets").
  **126 distinct labels out of 138.** So there was never anything to compile.
  → D-038; [`../ideas/final-state-representation.md`](../ideas/final-state-representation.md)
  rewritten; two stale `backlog.md` lines corrected.
- **M3 moved onto the critical path.** Aggregate coverage questions are the backbone of the
  evaluation — the one place the KG structurally beats document retrieval — and none of them are
  answerable until signatures exist.
- Recorded the user's **M4 idea**: keep the review diff as data (free labelled extraction error) →
  failure-mode taxonomy + a detector that sweeps the corpus for the same shape. Same machinery as
  the user-editing stage; build once (S-09).
- **Timeline established**: ~1 month of building, then 15 days for final tests and >50 pages.

## Decided

- **D-038** — final states are *parsed prose*, not compiled qualifiers: LLM emits
  `{object, count, comparator}`, code serialises the canonical id. The model never writes the id.
- **S-01/S-02** — the query system is the single entry point for users *and* agents; faithful base
  with LLM layers strictly on top (and `entity_occurrence`, not `entity`, is the faithful layer).
- **S-03/S-04/S-05** — router splits into LLM shape-classification + deterministic retrieval;
  queries are templates filled with retrieved ids; **SQL only** for querying, Neo4j for the view,
  hand-written templates for genuine multi-hop.
- **S-07** — agents never edit the extraction code; they file proposals for human approval.
- **S-10/S-11** — freeze the question set, split dev/test, tag every question, and **deliberately
  include dedup-sensitive questions** or Phase 3 has no signal.
- **S-12/S-13** — three-arm baseline plus a dated deep-research snapshot (corpus-restricted);
  deletion protocol measures **abstention** and **recovery** separately.
- **S-16** — **LangGraph for orchestration only**; prompts, LLM calls, retrieval and SQL stay
  hand-written; nowhere near `adjudicate.py` or the aliases layer. **LangChain rejected.**
- **S-19/S-20** — guided decoding everywhere structured; real tool calling; expose the query system
  as an **MCP server** (matches S-01 exactly).
- **S-22** — the evaluation harness is built **before** the query system, pointed at a stub.
