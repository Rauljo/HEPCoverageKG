# 2026-09-05

## Happened

**The arm results were mostly measuring a formatting property.** Went looking
for a per-arm × per-question-type × per-Gabriel-question breakdown of runs
54201-06 and found the two identical controls disagreeing completely on gf-03
(0.00 vs 0.89) and gf-08 (0.21 vs 0.00). The zeros were not wrong answers:

    gf-08 ctrl-b  "...are: [list of papers from the intersection]."
    gf-04 subgoal  seven CORRECT papers, listed by title, no ids     -> 0.00
    gf-07 reviewer "To finalize, run `papers_of` on the intersection" -> 0.00

`judged_set_f1` reads arXiv ids out of the answer text. That rule is right
(D-062). The agent simply kept writing answers with no ids in them.

Rate of that hard zero, over 108 set-scored questions per arm: reviewer 71%,
tool-examples 50%, control 35%, subgoal-status 35%, simple-answer 19%.

Decomposed, score = (prints ids) x (quality when it does):

    ctrl-a  0.222 = 0.65 x 0.277      reviewer       0.180 = 0.29 x 0.312
    ctrl-b  0.225 = 0.64 x 0.272      simple-answer  0.214 = 0.81 x 0.244
    subgoal 0.265 = 0.65 x 0.353      tool-examples  0.221 = 0.50 x 0.308

On the two Gabriel questions where ALL SIX arms printed ids, every arm scored
0.626. The whole spread was who happened to print a list.

- the reviewer is not reasoning worse -- it stops early (1.8 rounds vs 2.4) and
  writes a pointer. Its when-printed quality is ABOVE both controls.
- simple-answer's gain is the mirror artefact: prints more, knows slightly less
- subgoal-status is better on BOTH axes, so D-096's +0.038 survives as the one
  real effect

**Three bugs found underneath it**, all ours:

1. `graph.py` set `session.cited`; `systems.py` reads `answer_cited`. Every
   `--simple-answer` citation reached the scorer as uncited.
2. `resolve_citations` matched `papers_from` exactly, so "set_1_kept and
   set_3_kept" -- the commonest value the model writes -- dropped in silence.
3. `_papers_resolver`'s try/except wrapped the tool call but not the loop over
   its result, so a malformed `papers_of` raised out of the answer path the
   guard exists to protect.

**Also settled** the "were the embedding models run without a critic?" question:
only the QwQ ones. Every OpenRouter run went through `or_arm_job.sh`, which
pins `CRITIC_MODEL` to Llama-3.1-8B -- not a reasoning model, so D-105 never
touched it. The sharpest encoder measurement (qwen3.8-flash, noise 0.003) and
the temperature result both stand; the two QwQ encoder runs are void.

**The DIAS clone had drifted out of git entirely** -- see D-109. Three failed
submissions to find all of it.
