## Findings from reading the acquisition pipeline (all code-grounded)

- **Vocabulary flags, doesn't canonicalize.** `normalize_object_label` is called only in `qa.py`
  (a warn-check); the entity id is the model's verbatim `key` (`_entity_id`). → b_jet/b-jet/bjet.
- **The id namespace is ungoverned** (34 for ~22 kinds; abbrevs like `cs`; some namespaces mix
  kinds). Not validated anywhere, not even QA. `kind` IS a controlled enum, right next to the
  free-text `key`. → derive the id from `kind` + normalized slug.
- **`predicate_typing` = ~77% of quarantines (1,955/2,555)** — schema-typing, not physics. Biggest
  bucket (~1,400) is values-where-the-schema-wants-entities (already exempted by
  `VALUE_OBJECT_PREDICATES`), plus the `detector_object`/`object_definition` slip (same as b-jet).
  14% (370) have no finding → cross-pass adjudication. → "quarantined ≠ wrong".
- **Root cause of all three**: *the schema is validated, not used to construct* — ids and edges are
  whatever the model typed. Fix = guided/constrained decoding (also fixes empty signatures).
- **Families**: 31 predicates in 8 families; **one prompt per family** (~7 fire/paper), each prompt
  emits many predicates; each predicate lives in exactly one family. **Out-of-family predicates
  hard-fail the whole payload (`raise`) → a retry, and the observation is lost** — partly explains
  the retry imbalance, and is real signal discarded. **Entities + assertions are produced together**
  in one family answer, wired by `key`.
- **Same-predicate conflicts**: possible, but Gabriel's schema has no single-vs-multi cardinality,
  so within-pass conflicts aren't caught (only cross-pass, via adjudication). Raul's D-010/D-018
  handle it — a place the design is more principled.
