## Two ideas from the user, both adopted with a sharpening

- **Decomposition (S-53)** — deep-research systems recombine sub-*answers* (a model merging two
  paragraphs, where they leak errors). We can do better: `search` produces **named sets** (S-29), so
  decomposition recombines as **SQL set algebra**. Bonus: inclusion–exclusion then applies (S-34), so
  the decomposition makes the answer *checkable*, not just answerable.
- **Paraphrases (S-54)** — split in two. **Fuse the retrievals** with RRF (safe, already built, and
  it targets retrieval recall, the weakest link at scale). **Never merge disagreeing answers** — that
  is a union of things we cannot tell apart, i.e. a confidently wrong composite with a clean trace.
  Agreement instead becomes a **reported confidence** — S-52 promoted to a product feature.
- **Both deliberately not built yet.** They are ablation axes; building them before the harness moves
  the thing being measured.

## Harness — designed, not implemented

## The generated question set does not work, and that is the finding — S-58

**v1 (cluster = concept): 1 of 36. v2 (head word = concept): 0 of 36.**
A cluster is not a concept; head words are meaningless for descriptive labels (`b-tagged jet` → `'b'`,
`95% CL excluded mass limit` → `'95'`). It works only for branded names, which is why Pythia was right
and nothing else was.
**The cause is circular and worth stating plainly**: to write a question with a known answer you must
know which ids constitute the thing being asked about — *which is the aliases problem*. A generator
over an under-merged graph re-derives a worse deduplication, and fails differently each time.
**Resolution (S-58)**: truth must be **invariant to the concept boundary** — count narrow and broad,
keep only where they agree. **242 well-posed / 224 ambiguous = 52% survive**, and the 48% discard is
itself the measurement of how incomplete dedup is.
**Six tiers (S-59)** now defined, anchored by what makes their truth safe. **Tier A (per-paper) is the
backbone** — `paper_id` is a hard identifier, so ~540 questions with dedup-independent truth.
**Tier E** (unique anchor + hop) is the most valuable new shape: exact truth *and* multi-step
reasoning, which counting questions cannot test at all.

## The hour-long stall — S-61

*And the fix broke it differently first*: the worker thread made SQLite reject the main-thread

# 2026-08-02 (evening) — the aliases layer, rebuilt and re-run

## Six fixes, then a real run

**Found by reading the code (the "what's missing" review):** `aliases/context.py` was wired into
`evaluate.py` (the trial set) and **NOT into `run.py`** — so quality was measured on one system and
the 126,335 proposals were generated by another, weaker one. That is the single biggest defect of the
old output and it explains its errors (`leading` == `subleading`, `dilepton` == `four-lepton` are
exactly what graph context prevents).

Fixed together: (1) context wired in · (2) **keyed by `entity_id`, not label** — `label_to_ids` was
built and never read, and 144 labels map to >1 id, so verdicts could not be written back at all;
expansion costs 1.08x · (3) **LaTeX typography stripped before truncation**, keeping notation
(`E_T^miss`, `t\bar{t}` -> `ttbar`) · (4) **streamed to disk** as verdicts arrive · (5) **transitivity
paradoxes counted**, not just logged · (6) **dead theory-RAG slots removed** from the prompt.
Plus: `logging.basicConfig` in the CLI — `aliases deep --dry-run` printed *nothing*, because its whole
report is `logger.info`.

## The run

```
candidates 14,656 -> after guards 9,570 -> id_pairs 10,839
matched 2,262 · rejected 8,575 · errors 2 · paradoxes 1,287 · clusters 330
stability 111/111 identical across 3 runs = 100%
```

**The old file was 13x bigger (126,335) because it predates the bge-base swap AND the Tier 2.5
guards** — it started ~22:29 and finished 23:27, so it ran on the original code. Nothing about it is
comparable to what we produce now: different encoder, no guards, no context, no ids.

**Stability 100% at temperature 0** means the serving stack is deterministic, so any later precision
difference is real rather than noise. It does **not** mean the model is sure — see below.

## Transitive closure is over-merging (the big finding)

330 clusters from 2,262 approved pairs. The largest holds **75 statistical methods** — profile
likelihood, the CLs procedure, log-normal nuisance constraints — welded together because every
*neighbouring* pair looked similar. Nobody judged the ends of the chain.
A real worked example, from the data:
```
model REJECTED: "Lepton efficiency and energy scale (tag-and-probe)"
             != "Lepton energy/momentum scale and resolution"
model APPROVED: A == B == C == D   (a 3-link chain joining exactly those two)
```
One of those four verdicts must be wrong. **1,287 of 8,575 rejections (15%) are contradicted this
way.** This is semantic drift along a chain — the NELL lesson, observed in our own output.

**Decision (user's, and it is the right split): deduplication answers IDENTITY and emits PAIRS;
deciding that several versions form a FAMILY is the grouping layer's job (S-28).** The dedup step
must never chain. `writeback_plan()` implements that: 603 pairs clean, 1,659 in tainted chains,
nothing written to `same_as`.
*Also noted by the user*: canonicalisation is **non-destructive** (`entity_canonical` is a lookup;
originals and per-paper occurrences are untouched), so a wrong merge costs wrong counts until it is
deleted, not lost data. The stakes are lower than they look.

## Whole-cluster checking works, and is cheap

`aliases clusters` shows the model an entire small cluster at once and asks "one thing, or split?".
**122 clusters of 3-8 members, one call each, ~2 minutes, 0 errors: 43 hold together, 79 should be
split.** So chaining fails at size 3 too, not only in the giant blobs.
The splits are physics-correct — it separated `ttV` (any vector boson) from `ttZ` (specifically Z),
which is the exact pair flagged as needing a physicist earlier the same day. **Seeing the whole set
is what reveals the distinction**; pairwise cannot.
Deliberately its own CLI action, not a phase of `deep` — different question, and it reads a file so a
prompt change costs minutes rather than another hour.

## Sampling measures something temperature 0 cannot

`aliases confidence` — 111 pairs x 5 samples at temperature 0.7:
```
5/5 agree 101 · 4/5 agree 4 · 3/5 agree 6      (91% unanimous)
sampled majority DISAGREES with the approved verdict: 3 pairs
```
Greedy decoding hides doubt by construction. Sampling agreement is a **behavioural** confidence
signal, unlike the self-reported `confidence` field. It flags genuinely debatable cases in both
directions (`kappa_F` vs `kappa_mu` correctly doubted; `POWHEG v2` vs `Powheg Box v2` doubted and
probably fine). **Whether agreement predicts correctness is a hypothesis for the hand labels, not an
assumption** — a model can be consistently wrong.
