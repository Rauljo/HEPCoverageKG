# 2026-08-01 — the evaluation chapter, designed end to end

A whole session on one question: **how do we evaluate this with no curated ground truth?** Gabriel
will supply interesting questions and can review a little, but he will not produce answers.
No code written. `system.md` → **v1.4**, §4 rewritten, **S-32 … S-52**.

## The reframing that unlocked it

The instinct — *"no ground truth, so we need a judge model"* — skips the fact that **three different
things are being evaluated**, and that only one of them is scarce:

```
L1  did the agent query the graph correctly?   →  the GRAPH is ground truth   free, exact, unlimited
L2  does the graph match the papers?           →  the papers                  one reading pass
L3  is the answer useful to a physicist?       →  only Gabriel                scarce
```

**Almost everything we are building is L1** — planner, retrieval, dedup, templates, abstention, the
LangGraph loop. For all of it the graph is *perfect* ground truth. Thousands of exact labels, no
human, no judge (S-32).

And the consequence that had been invisible: today, when an answer is wrong, **we cannot tell
whether the agent asked badly or the fact was never extracted.** One contaminated number instead of
two honest ones. Fixing that is what the reference reader is for.

## The reference reader — the user's idea, and the strongest item in the plan

> *"Get a big LLM, give it the 60 papers, tell it to read carefully for an hour, and answer the
> questions. That's a ground truth. Then give the same corpus and questions to other systems."*

It is the only thing in either of our plans that measures **L2**, and it gives every baseline a
shared target. Adopted with four changes (S-37):

- **one paper at a time, not 60 at once** — 60 papers ≈ 700k–900k tokens, long-context attention
  degrades in the middle, and aggregation must be Python arithmetic, not model output
- **constrained to our schema and granularity** — otherwise "same fact, different shape" is
  indistinguishable from disagreement
- **a third model** — extraction is Sonnet, querying is Qwen, so the reader must be neither
- **a strong reference, never "ground truth"** — 3× per paper for self-agreement, a verbatim quote
  required for every claim (which also blocks answering from pretraining memory), ~20 quotes
  hand-checked. If it is 90% right, a perfect system scores 90%, and that ceiling must be stated.

Its output has **the same shape as an `assertion` row**, so the two graphs can be diffed (S-39).
Facts in the reader's but not ours are **extraction gaps** — the *silent omission* failure the vault
already names as dominant, and which nothing else here would catch.

## Corrections — both from the user, both real

**1. `same_id` is not dedup ground truth.** The vault already says 347 shared ids against **334
divergent**. My "held-out `same_id` pairs give free recall" was wrong. Replaced by three *noisy*
sources (same_id, normalisation-identical, LLM judge) with their own precision measured — plus the
measurement that needs no labels at all: **run the dedup-sensitive counting questions with dedup on
and off at 10/20/40/60 papers** (S-51).

**2. Reading all 2,969 papers is affordable.** ~45M tokens per pass ≈ a few dollars on a cheap fast
API, ~$130 on a mid one, or roughly a day of DIAS time. I had treated it as prohibitive. It is not,
and that changes what the growth curve can be (S-37, S-47).

**3. GraphRAG is not a like-for-like comparison** — it builds an induced graph for sensemaking, not
a coverage map. Largely correct. Reframed from *"we beat it"* to **"does hand-curating a typed
schema buy anything?"** — which is the obvious challenge to this project (*"why not just run
GraphRAG?"*) and had no answer. Report per question type, and **expect to lose on open-ended
sensemaking**; reporting that is what makes the counting win credible (S-44).

**4. A-vs-B breaks when the two answers address different things.** Correct, and pairwise collapses
there. Fixed structurally: **build a checklist from the graph/reader *before* anyone sees an answer,
then score both against the same list.** Nobody compares anything; "they answered different things"
just means one missed the list. Gabriel's role shrinks to *"is this the right list?"* — ten lists,
twenty minutes, once (S-42).

## Two finds while checking the pipeline (D-041, D-042)

- **`--provider openai`** — Gabriel's extraction pipeline accepts any OpenAI-compatible endpoint, so
  it runs against **our own vLLM**, with `HEPKG_CORPUS_ROOT` repointed at the DIAS corpus. The pilot
  used his Claude subscription and needed a sleep/probe loop for usage limits. **Extraction is not
  blocked on Gabriel; it is bounded by cluster time, which we control.**
- **`GROUND_TRUTH.md` already exists** — ~17 papers, hand-written from the papers' selection
  sections: cuts, object definitions, multiplicities, expected event class. It even self-corrects
  (2103.01290, AK8 vs AK4). It is about **final states**, i.e. M3. So *"we have no ground truth"* was
  never quite true. **Stale**: last touched 2026-07-05, while the repo moved to 2026-07-27
  (`canonical entity map v2 + facet layer`). Physics does not go stale; field names might.

## Also decided

- **Expert time buys calibration and disagreements, never labels** (S-40). ~50 blind pairwise for a
  κ against the automatic judge; ~40 **graph-vs-graph disagreements** with both quotes shown (sample
  where the uncertainty is — everywhere the graphs agree the answer is already known); ~20 quote
  adjudications; ~10 checklist checks. **Under two hours, total.**
- **Plan type-checking against the schema card** (S-35) — turns 2026-07-31's one unguarded failure
  (`result_has_systematic` used backwards, "nothing exists" against 1,148 rows, clean trace) into a
  guard **and** a metric: *"plan validity: X% type-correct on first attempt"*.
- **`missing:` not "why"** (S-50) — model justifications are often unfaithful, so never a metric.
  One short field on continuation rounds saying what the previous results *lacked*: cheap, targets
  the real weakness (knowing when to stop), and **mechanically checkable** against the retrieved rows.
- **No benchmark measures aggregate coverage** (S-45). Saying so with the survey behind it is a
  strength. chATLAS_Benchmark is the one in-domain option — an hour of scoping decides it.
- **Retrieval metrics**: Recall@k and MRR as headline, NDCG only where relevance is genuinely graded
  (S-48). Stratify the draw by rare/common, many-spellings/one, **merged/singleton** — the last one
  tests directly whether dedup helps or hurts retrieval.
