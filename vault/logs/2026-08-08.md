# 2026-08-08 — the facet and signature layers land; the aliases layer stops under-merging

## Happened

**Aliases Tier 1 gained label matching (D-050).** Diagnosis first: every merge in the graph came from
`normalize` (328) and `spelling` (19), all scoring 1.0 — no judgement call had ever been applied, so
"should we be less conservative" did not yet mean anything. And Tier 1 folds the **entity id slug**,
never the label, so seven entities all labelled `MadGraph5_aMC@NLO` sat in four clusters. Measured:
**41 groups of byte-identical same-kind labels split across clusters.**

Added `label_exact` and `label_norm`. Result: **+138 / +20 proposals, 41 split groups → 0.** All 20
folded merges read by hand and correct (hyphenation, capitalisation, spacing around `=`); no version
boundary crossed. Node counts fell — generators 223→150, systematic uncertainties 803→716, detector
objects 227→191, collision systems 24→12.

The label fold **keeps the decimal point** unlike the slug fold: slugs are identifiers where
`pythia8.210` and `pythia8210` are one thing, but labels carry cut values and stripping the dot folds
`pT > 2.0 GeV` onto `pT > 20 GeV`.

**Facet + signature layers imported by DERIVING them, not importing them (D-052).** Recomputing from
our own graph reproduces all 60 of the supervisor's analysis cards exactly, so his
`pilot/analysis_facets.jsonl` is a snapshot of a function; it is kept as a **test fixture**, the
oracle, never as production data. `vocabulary.py` vendored verbatim and hash-pinned (plus a 30-line
`models.py` for the one enum it imports — it was *not* pure stdlib as first assumed);
`signatures.py` **ported**, with two tests running our port and upstream's module over every
candidate and asserting identical verdicts. Upstream modules are loaded **from git at the pinned
revision**, so a branch checkout cannot silently skip the tests that validate our copies.

**The bug parity caught**: first implementation derived from `entity.label` and got wrong answers on
8 papers. `entity.label` is a rollup — the schema calls entity_id *"convenience rollup ONLY, not
identity"*. **312 entity_ids carry different labels in different papers**, and the label decides the
tag (`2107.12553` wrote "b-tagged small-R jet"; the rollup says "b-tagged jet" → BJet). Facets are
per **occurrence**. Fourth silent-SQL-shape trap in this project.

**Query layer: `facets` and `facet_entities` (D-053, D-055).** All Tier 1 gold answers reproduce
through the planner executor — Q1 18 papers, Q2/Q3/Q5 exact sets, including his Q5 trap.
`facet_entities` answers the *inventory* question (which distinct things, collapsed by alias
cluster) — the shape the dedup ablation needs, because it is the only one whose number moves when
merging changes.

**The vocabulary block was built and then thrown away (D-054).** Shipping the whole closed vocabulary
in the schema card (~590 tokens) would have put **five of the seven** Tier 1 gold keys into the
system prompt. Not hypothetical: writing the prompt section that *warns* about leakage, I used `ABCD`
as the worked example and the new regression test caught it. Replaced by facet keys on **search
hits** — measured at **rank 1, 8 times out of 8** with BM25 alone on the phrasings his questions use.
Card cut to 137 tokens of field names and coverage, no values.

## Decided

- **D-050** Tier 1 keys on the label as well as the id; under-merging is not the safe direction.
- **D-051** merging moves *inventory* counts, not *paper* counts (0.48% of facts) — the dedup
  ablation must be scored on inventory questions or every arm returns the same number.
- **D-052** derive the facet + signature layers rather than importing them; two tables and a **view**.
- **D-053** `facets` returns the entity trail, never bare paper ids.
- **D-054** search hits carry facet keys; the prompt never lists them. Describe the tool, do not
  prescribe the strategy — *which rung the agent picks is the thing being graded*, so
  "prefer the cheapest route" is kept as ablation arm C, not shipped.
- **D-055** `facet_entities`, the inventory shape.
- Idea captured: [discovered-grouping-layer.md](../ideas/discovered-grouping-layer.md).

## Measured

```
facets            82.0% of 4,202 occurrences tagged
                  worst: detector_object 74.1%, systematic_uncertainty 70.8%
signatures        734 leaves from 2,692 candidates, 0 native, 46 subchannel flags
                  -> the AND/OR distinction survives extraction ~2% of the time
tests             427 passing, 2 skipped
```

Misses split three ways and need different repairs: **notation** (`$E_T^{miss}$` folds to `e t miss`,
so `\bmet\b` never fires — a fold bug, in the file we deliberately cannot edit), **narrow patterns**
(`$b$-jet identification calibration` should be FlavourTagging), and **genuinely absent concepts**
(`OS-SS subtraction`, `h_damp`). Only the third needs new tags.

**Precision is still unmeasured.** 68 entities carry 3+ tags, and at least one is plainly wrong:
`"Data-driven control sample … replacing simulation"` is tagged `SimulationBased` — a regex cannot
see negation. Recall is measured; precision is not.
