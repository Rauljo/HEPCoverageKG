# 2026-07-24 — importer step 2, and a correction that reshaped the conflict rule

*(Continuous with the 2026-07-23 session-2 design work; step 1 is logged there.)*

**Happened**: Built step 2 of the importer. Before coding it, checked how the supervisor actually
computes `bundle_id` — which turned out to invalidate part of the D-024 conflict design, so that
got fixed first. Also added status-history preservation after a good user question. 28 tests green.

**The correction (→ D-027)**: `bundle_id = content_id("bundle", {schema, paper, source_hash,
normalization})` — **identity only, no assertions or statuses**. Reproduces exactly on 7/7 real
bundles and all 4 fixtures. Consequences:
- `bundle_id` is **stable across re-extractions of the same paper**, so "same bundle_id + changed
  content → abort" would have aborted *every* legitimate milestone-4 re-import.
- All 3 fixtures share one bundle_id but have 3 different whole-bundle fingerprints → the bundle
  level **cannot** distinguish a valid re-import from corruption. Conflict detection had to move
  **per assertion**.
- `assertion_id` is claim-derived (`{paper, family, subject, predicate, object, value, signature,
  qualifiers, evidence}`), so claim fields *cannot* change without producing a new id; and
  `review.py` only ever sets `status` on an existing assertion (corrections are appended as new
  assertions). Hence **`status` is the only mutable field** — verified against the fixtures:
  accepted→corrected differs only in status (allow), accepted→conflicting differs in `notes` (abort).
- Earlier claim that the fixtures "reuse a bundle_id as an artificial test handle" was **wrong** —
  they legitimately share it.

**Also decided (→ D-028)**: `assertion_status_history` table. Overwriting `status` in place would
lose the prior value (`expert_decision` records *that* a decision happened, not what it moved
*from*), and M4 requires *showing* promotions land. Append-only, **changes only** (not initial
inserts), and explicitly scoped: it records what changed **between our imports**, never the
supervisor's internal lifecycle.

**Step 4 also DONE** (73 tests green in total): `ingest/validate.py`, the semantic gate.
- **Design principle settled**: *errors* = contract rules + anything the store itself would refuse
  (FK/PK/CHECK), pre-checked here so a bad bundle names the offending record instead of throwing a
  cryptic SQLite error mid-transaction; *warnings* = metadata inconsistencies and authenticity
  signals that cannot corrupt the scientific graph.
- **Errors**: accepted⇒evidence · exactly-one-object-shape · in-bundle referential integrity
  (subject/object/evidence/`revision_of`/`activity_id`/decision refs/evidence→block) · ids unique
  **within** a bundle (all 8 record types — note across bundles entity_ids repeat *by design* and
  merge) · `paper.arxiv_id == source.paper_id` · `evidence.source_hash == source.source_hash`.
- **Warnings**: inauthentic `bundle_id`; a non-quarantined assertion with no evidence; dangling
  qa/completeness references.
- **`revision_of` is the one the database cannot guard** (soft pointer, no FK — step 1), so this
  gate is its only check. That closes the promise made when we made it soft.
- **Pre-verified every rule against all 60 bundles before writing it: 0 violations.** After
  building, ran it over all 60 + the fixtures: **0 warnings raised** — the pilot data is fully
  internally consistent, including no inauthentic bundle_ids and no anomalous evidence-less
  assertions. (Incidental finding: all 450 evidence-less assertions are `quarantined`, matching
  `runtime.py`, which quarantines unlocatable quotes.)
- **Gate boundaries now pinned by tests**: `invalid_accepted_without_evidence` passes the *shape*
  gate but is **rejected here**; `conflicting_bundle` **passes here** because its defect is a
  conflict against stored data — step 6's job, not this gate's.

**Step 6 also DONE** (91 tests green): re-import guard in `importer.py`.
- A read-only check runs **before any write**. New bundle_id → import. Same bundle_id + identical
  content hash → **no-op** (`skipped=True`). Same bundle_id + changed content → classify each
  incoming assertion by a stored `identity_hash` (new nullable column = claim hash minus status):
  any non-status change under an existing id → **`BundleConflictError`, abort** (nothing written,
  so no transaction to roll back); only status changes / new claims → **skip + warn** naming what it
  saw ("applying re-import updates is milestone 4").
- **Scope decision (user)**: build only the M1 half now (no-op + conflict-abort, conditions 2 & 3);
  the *apply-updates* reconciler is milestone 4. A non-conflict re-import is **skipped with a
  warning** rather than half-applied — user's call ("identify those cases and flag them for the
  future"). So `assertion_status_history` (D-028) exists but nothing writes to it yet — that lands
  with the M4 reconciler.
- **Correction to an earlier worry**: the entity_occurrence re-insert "complication" doesn't bite in
  M1 or M4 — for M4 review re-imports the entities are identical (review only touches statuses + adds
  assertions), and M1 never writes on a changed re-import at all (conflict is decided from assertions
  first). bundle_id depends only on the *source*, so only a re-extraction on unchanged HTML could
  change entities under a fixed bundle_id — out of scope; flagged for later.
- **Verified**: all 60 imported twice → 60/60 skipped, counts unchanged (still
  14,188/11,309/2,555/324); `conflicting_bundle` aborts leaving the DB byte-for-byte untouched;
  status-only re-import warns instead of conflicting.
