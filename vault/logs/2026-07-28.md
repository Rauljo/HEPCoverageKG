# 2026-07-28 — audited the Antigravity work; hardened Tiers 2/3; DIAS on git

**Happened**: reviewed everything built in Antigravity (schema fix, Neo4j export, aliases Tiers 2/3,
the DIAS run), found and fixed six real defects, re-measured the embedding choice from scratch, and
put the cluster on a normal git workflow. Six decisions taken (**D-032..D-037**).

## Audit of the Antigravity session

**Solid and verified**: the entity-identity schema fix is exactly right; the Neo4j export is clean —
60/6,047/4,772/3,766 nodes and 6,047/6,047/14,188 edges with **zero dangling references**, every
occurrence carrying exactly one `RESOLVES_TO`, and `hepkg:object:b-jet` reached by **27 papers**
through one canonical node. That is the "one real BJet node" design working end to end.

**Six defects found** (all fixed, all now covered by tests):
1. `build()` ran the deep pass unconditionally → Tiers 1/1.5 needed a GPU + live LLM. → **D-033**
2. The deep pass wrote to a CWD-relative hardcoded path. **Running `pytest` from the repo root
   destroyed the real 68MB result file** (recovered intact from DIAS). → **D-033**
3. LLM failures were recorded as `is_match=False`. → **D-034**
4. SciBERT is an MLM checkpoint with no similarity head. → **D-035**
5. Three bugs in `guards.py`, which had no tests at all. → **D-036**
6. `scikit-learn` imported but absent from requirements — **removed** the dependency instead of
   adding it (normalise at encode time, dot product = cosine).

**Report discrepancies worth remembering**: `scratch/check_contradictions.py` did not exist, so the
742-contradictions result was unreproducible from the repo; "repository remains pristine" was untrue
(6 modified + 5 new files, nothing committed); the cluster's SQLite was recorded as 3.7.17 but is
**3.36.0**. Lesson repeated for the sixth time this project: **check the artefact, not the summary.**

## The measurement that mattered

Re-ran the encoder choice as a bake-off on HEP probe pairs rather than trusting reputation (full
table in **D-035**). Only **bge-base** separates synonyms from look-alikes (+0.031); **bge-large is
worse than bge-base** despite 3× the size. Jaccard is kept over Levenshtein because every dangerous
HEP look-alike *and* every true spelling variant is a one-character swap, so edit distance measures
the wrong thing entirely.

**Result: 126,335 → 14,656 candidates (9,570 after guards) at the same 0.85 threshold.** ~13× fewer
LLM calls. Reproduced *exactly* on DIAS (different Python, SQLite and numpy).

**The error-rate question is now answered**: the old 126,335-pair run contained **75 errors
(0.059%)** — 74 timeouts, one parse failure. The contradiction analysis stands. The `status`/`error`
fix still matters for shared APIs, but it did not invalidate past results.

## Method note — a fix that passed its tests and was still wrong

The first repair of the guard's number comparison (digit signatures instead of token sets) passed
all 29 unit tests, then failed on real data: it turned **86 LLM-confirmed synonyms** into false
vetoes because `"3L channel (exactly 3 light leptons)"` signs as `"33"` and `"(3ℓF)"` as `"3"`. The
probe set could not have caught it. **Unit tests pin intent; only the corpus tests reality.** Final
rule needs *both* views to agree — see **D-036**.
